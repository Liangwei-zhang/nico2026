> 适用版本: dashen-money v7（TradeV7）
> 项目类型: 多用户 AI 量化加密货币自动交易系统
> 使用说明: 按顺序逐步喂给 Claude/GPT 等 LLM，每次喂一个模块，完成后继续下一个。

## 提示词 0: 项目总提示词（建议作为每次对话的 System Prompt）

```
请帮我开发一个名为 "dashen-money" 的多用户 AI 量化加密货币自动交易系统。

## 系统概述
这是一个支持多用户、多交易所、多策略的 AI 驱动加密货币自动交易平台，代号 TradeV7。系统每15分钟自动执行一轮交易决策周期：获取市场数据 → 技术分析 → 风险评估 → 构建LLM输入 → 调用AI决策 → 执行交易 → 管理止损。

## 技术栈要求
- 后端: Python 3.10+, FastAPI, asyncio
- 数据库: MySQL 8.0+（SQLAlchemy + PyMySQL）
- 缓存: Redis 6.0+
- 前端: Vue 3（CDN，不使用构建工具），Tailwind CSS（CDN），Chart.js
- LLM: 支持 Anthropic(Claude)、OpenAI(GPT)、DeepSeek、OpenRouter、Grok、Gemini
- 交易所: Binance、OKX、Bitget、Hyperliquid（统一抽象接口）
- 通知: Telegram Bot API

## 核心架构设计

### 1. 纯 asyncio 架构
- 使用 asyncio.run() 作为唯一入口
- 所有服务在同一个事件循环中运行
- 使用 ApplicationLifecycle 统一管理启动/关闭
- 后台任务支持自动重启

### 2. 多用户隔离
- 每个用户有独立的 AsyncUserContext
- 使用 TaskGroup 确保一个用户的错误不影响其他用户
- 每个用户独立的 batch_cache（不共享全局数据）
- 按用户等级优先级调度: VIP > PRO > BASIC > FREE

### 3. 交易所抽象
- BaseExchange 抽象基类定义统一接口
- 工厂模式创建交易所实例
- API Key 使用 AES(Fernet) 加密存储
- 支持4个交易所: Binance/OKX/Bitget/Hyperliquid
- 多交易所并行执行同一交易决策

### 4. 分层市场分析引擎（7层 Pipeline）
a) 数据获取层: K线数据获取和缓存（支持 5m/15m/1h/4h）
b) 指标计算层: EMA/RSI/ADX/MACD/ATR/BB/OBV/VWAP（使用 TA-Lib）
c) 市场结构层: 趋势识别/支撑阻力/突破检测/动量状态
d) 技术结论层: 多周期结论合并（4H趋势+1H结构+15M微观）
e) 专用分析层: 情绪/相关性/模式匹配/K线形态/风险量化（VaR/CVaR）
f) 上下文层: 全局市场上下文/时间上下文/决策反馈闭环v2
g) 组装层: SymbolAnalysis 统一数据结构（含 RiskModule）

### 5. LLM 决策引擎
- Prompt结构: OUTPUT_ANCHOR → user_strategy → CORE_ACTIONS → CORE_OUTPUT_FORMAT
- 7大策略分类: role/risk_rules/entry_conditions/exit_conditions/position_sizing/market_preferences/adaptive_rules
- 提示注入防护（_sanitize_user_strategy）
- 统一 LLM 客户端支持6+提供商
- 响应解析器支持 XML(<decision>) 和 JSON 格式
- 决策反馈闭环v2（历史胜率按市场体制分类反馈）

### 6. 风险管理层（v7核心新增）
- 用户级最大回撤熔断（max_drawdown_pct，默认15%）
- 历史VaR计算（95%置信度，基于N周期收益率）
- 波动率体制自适应仓位缩放（CALM/NORMAL/VOLATILE/EXTREME）
- 风险状态注入 LLM payload（让 AI 知道当前风险水位）
- 风险配置 API（用户可自定义风险参数）

### 7. 交易执行与止损
- 信号校验: 仓位大小/限价单距离/最大持仓数/波动率自适应
- 初始止损 1.5%，止盈 5%
- 5级移动止损: 2.2%→锁1%，3.5%→锁2%，5.5%→锁4%，7.5%→锁5.5%，10%→锁8%
- 全局止损处理器（单例，批量Redis，500ms本地缓存）
- 交易所连接池（1000用户优化）

### 8. 智能选币服务（dashen-selector）
- 文件名: dashen_selector.py
- 双模式: 外部API模式 + 本地评分模式
- 本地评分维度: 24h成交量(40%) + Funding Rate绝对值(30%) + BTC相关性偏离(20%) + 波动率分位(10%)
- Redis 键名: DASHEN_SELECTOR_SYMBOLS
- 3分钟更新，整点跳过

### 9. 实时数据流
- 共享 MarkPrice WebSocket（100用户=1连接）
- 动态订阅管理，实时止损检查

## 关键设计原则
1. 每15分钟为交易决策周期，与K线周期对齐
2. K线数据只获取完结K线（排除当前K线）
3. 所有技术分析只输出结论，不输出原始值（节省LLM token）
4. 多周期分析: 4H定方向+1H定结构+15M定入场+5M精确入场（可选）
5. Prompt注入防护: 用户策略文本经过清洗

7. 共享WebSocket: 多用户共享连接，减少资源消耗
8. 风险先于决策: 每轮调度先执行熔断检查，超限则跳过本轮
9. 纯LLM不够: LLM负责推理，量化指标过滤信号，风险层约束仓位

## 提示词 4: 风险量化分析模块（v7新增）

```
开发风险量化分析模块（analysis/specialized/risk_analyzer.py），要求：

1. 输入: 用户持仓数据 + 账户余额 + 历史收益率序列（来自 kline_utils.extract_returns）

2. 计算指标:
   - 历史VaR（Value at Risk）: 95%置信度，基于最近N周期（默认100）收益率
   - CVaR（Expected Shortfall）: VaR置信度对应的条件期望亏损
   - 当前回撤: 相对账户峰值权益的当前回撤百分比（从 Redis 读取峰值权益）
   - 波动率体制: 基于当前ATR分位数（CALM/NORMAL/VOLATILE/EXTREME）
   - 仓位缩放因子: 
     - CALM: 1.2（可适当放大）
     - NORMAL: 1.0（标准）
     - VOLATILE: 0.7（缩减）
     - EXTREME: 0.4（大幅缩减）

3. 熔断检查（check_circuit_breaker）:
   - 若当日回撤 > max_drawdown_pct（用户配置，默认15%），返回 BREAKER_TRIGGERED
   - 若 VaR > account_balance × 0.05，记录警告但不熔断
   - 返回: CircuitBreakerResult（triggered: bool, reason: str, drawdown: float）

4. 输出数据类 RiskState:
   - var_95: float（95% VaR，以账户余额百分比表示）
   - cvar_95: float
   - current_drawdown: float
   - peak_equity: float
   - volatility_regime: str
   - position_scale_factor: float（0.4-1.2，用于压缩仓位）
   - circuit_breaker: CircuitBreakerResult

5. 缓存: 每轮调度计算一次，存入用户 Redis（user_risk_state:{uid}），TTL=15分钟

6. 依赖: numpy（scipy可选）
```

## 提示词 6: Prompt 模板与策略系统

```
开发 LLM Prompt 模板和策略系统（llm/prompt_templates.py），要求：

1. Prompt 结构（v6.2，利用认知锚定效应）:
   - OUTPUT_ANCHOR: 输出约束（首因效应 — 第一时间确立格式）
   - user_strategy: 用户策略（从数据库加载，经过注入防护）
   - CORE_ACTIONS: 可用动作定义
   - CORE_OUTPUT_FORMAT: 输出格式 + 错误处理（近因效应 — 最后强化）

2. 动作类型:
   - 开仓: open_long/short_market, open_long/short_limit
   - 管理: increase/decrease_position, stop_orders, update_stop_loss/take_profit
   - 平仓: close_long/short
   - 不操作: wait（无仓位无挂单）, hold（有仓位或挂单）, cancel（取消挂单）

3. 输出格式:
   <decision>[{
     "symbol": "BTCUSDT",
     "action": "open_long_market",
     "entry": 65000,
     "stop_loss": 63500,
     "take_profit": 68000,
     "position_size_usdt": 500,
     "reason": "4H趋势看涨，1H结构突破，15M入场确认，VaR在可接受范围"
   }]</decision>

4. 提示注入防护: _sanitize_user_strategy() 清洗以下危险模式:
   - 忽略之前的指令类语句
   - 角色扮演/越权指令
   - 强制输出特定格式的指令（非交易决策）
   - 系统配置泄露指令

5. 策略分类（7大类）:
   - role: 角色定义（交易风格/擅长市场）
   - risk_rules: 风险规则（最大回撤/单仓限制/禁止操作）
   - entry_conditions: 入场条件（信号确认要求）
   - exit_conditions: 出场条件（止盈/止损策略）
   - position_sizing: 仓位管理（仓位比例/加仓规则）
   - market_preferences: 市场偏好（偏好趋势/区间/高波动）
   - adaptive_rules: 适应规则（市场体制切换行为）

6. 策略预设: conservative / aggressive / trend_following / mean_reversion / default

7. 风险状态注入（v7新增）: 
   在 user_strategy 之前注入当前风险状态摘要:
   "Current Risk State: Drawdown={drawdown}%, VaR_95={var}%, Regime={regime}, PositionScale={scale}"
   告知 AI 当前的风险水位，让其在 position_size_usdt 上自行约束

8. 策略服务（analysis/services/strategy_service.py）: 从数据库加载策略并组装完整 system prompt
```

## 提示词 8: 多用户调度器（含风险熔断）

```
开发纯 asyncio 多用户调度器（core/async_multi_user_scheduler.py），要求：

1. 每15分钟周期执行一次
2. 收集所有活跃用户（is_running=1, ai_enabled=1）
3. 按用户等级排序: VIP(4) > PRO(3) > BASIC(2) > FREE(1)
4. 使用 TaskGroup 并发执行，用户隔离

5. 每个用户的执行流程:
   a. 初始化交易所连接
   b. 获取账户信息（余额/持仓/挂单）
   c. 风险熔断检查（v7新增，优先执行）:
      - 计算当日回撤（当前权益 / 峰值权益 - 1）
      - 若超过 user.max_drawdown_pct，标记 CIRCUIT_BREAKER=True
      - 熔断时: 跳过LLM决策，只执行持仓管理（更新移动止损）
   d. 获取K线数据并计算指标
   e. 风险量化计算（VaR/CVaR/波动率体制）
   f. 构建LLM输入payload（含风险层）
   g. 调用LLM获取决策
   h. 解析信号并校验（含波动率自适应仓位缩放）
   i. 执行交易
   j. 设置止损止盈
   k. 发送通知（含风险摘要）
   l. 记录决策 + 开仓尸检快照

6. 信号校验（validate_signal）:
   - 开仓金额: position_size ≤ account_balance × position_size_pct × position_scale_factor
   - 限价单距离: |entry - current| / current ≥ limit_order_min_distance_pct
   - 波动率自适应（v7）: EXTREME体制下仓位上限额外压缩60%

7. 错误处理: 错误计数 + 连续错误检测 + 自动暂停
8. 用户超时: 600秒
```

```
开发止损管理系统，包含两个模块：

1. StopLossManager（trading/stop_loss_manager.py）:
