# dashen-money 多用户 AI 量化交易系统 — 最细粒度拆解文档

> 项目名称: dashen-money (TradeV7)
> 项目类型: 多用户 AI 量化加密货币自动交易系统
> 技术栈: Python 3.10+ / FastAPI / asyncio / MySQL / Redis / Vue 3 / Tailwind CSS

## 研究背景 — 2025年行业现状

在构建 dashen-money 之前，有必要了解当前学术界和机构的最新进展，这直接影响了本系统的设计决策。

**学术研究方向**

2025年量化加密交易领域的核心趋势：多时间框架强化学习（Multi-Timeframe RL）被证明可显著提升信号质量；A2C算法在加密货币期货组合交易中表现优异，高频（10-60min）与低频（日线）策略统计性差异显著；CNN-PPO混合方法在加密货币交易中相比纯RL提升约17.9%；LLM与RL的融合（"LLM教练 + RL执行者"架构）成为新范式。

**机构动态**

JPMorgan向AI量化基金Numerai注资5亿美元（AUM从6000万增至9.5亿，2022-2025）；AI驱动对冲基金相比传统量化每年额外超额收益约3-5%；2025年加密对冲基金中AI系统占比已超55%；CoinDesk 2025年12月报告确认：专用AI交易Agent（风险调整优化）显著优于通用LLM直接交易，GPT-5/DeepSeek/Gemini在Hyperliquid交易竞赛中仅勉强跑赢市场。

**对dashen-money的启示**

纯LLM决策不够，需要与量化指标深度融合；用户可定制的风险参数（最大回撤、VaR约束）比纯P&L优化更接近机构水准；决策反馈闭环（历史胜率→AI自我校正）是alpha可持续的关键。

## 二、模块拆解 — 最大细化

### 2.1 入口与启动模块

#### 2.1.1 `main_async.py` — 系统启动入口

**职责**: 纯 asyncio 架构的多用户交易系统启动入口

**启动序列**:
1. 设置线程栈大小（512KB，节省内存）
2. 加载 .env 环境变量
3. 配置日志系统
4. 初始化数据库表
5. 初始化邀请返佣表
6. 初始化用户上下文管理器（同步+异步）
7. 初始化全局 HTTP Session
8. 初始化交易所符号可用性
9. 预热 Binance/OKX/Bitget 公共数据缓存
10. 关闭非管理员测试网配置
11. 预热策略配置缓存
12. 初始化全局止损处理器
13. 初始化风险感知层（新增v7）

**后台任务**:
- `scheduler`: 交易调度器（15分钟周期，自动重启）
- `commission`: 返佣服务（自动重启）
- `notifier`: 消息推送 worker（自动重启）
- `dashen_selector`: dashen智能选币（3分钟更新）
- `global_market_fetcher`: 全局市场数据获取（5分钟更新）
- `web`: uvicorn Web 服务器

**关闭序列**: 停止调度器 → 关闭HTTP Sessions → 停止用户服务 → 停止返佣 → 停止止损处理器 → 关闭Redis → 关闭公共缓存 → 关闭数据库引擎

---

#### 2.1.2 `dashen_selector.py` — dashen智能选币服务

**职责**: 定期从外部API + 本地评分模型筛选最优交易标的

**核心逻辑**:
- 每3分钟触发一次
- **模式A（外部API模式）**: 调用 `https://token.dashen.wang/latest` 获取筛选列表
- **模式B（本地评分模式，新增v7）**: 对活跃币种按以下维度打分
  - 24h成交量排名（流动性权重 40%）
  - Funding Rate绝对值（情绪偏离权重 30%）
  - BTC相关性偏离度（独立性权重 20%）
  - 近期波动率分位（动量权重 10%）
- 排除特定币种（如 PAXGUSDT 等稳定币对、极低流动性币种）
- 存储到 Redis `DASHEN_SELECTOR_SYMBOLS` 键
- 整点跳过执行（Funding结算时段规避）
- 输出日志：入选/淘汰原因，供调试和策略优化

**为什么重要**: 2025年研究表明，主动的币种筛选（而非被动接受所有交易对）可以显著提升LLM决策质量——更少的噪声币种意味着更精准的分析。

#### 2.1.3 `core/lifecycle.py` — 生命周期管理器

#### 2.2.7 `core/async_multi_user_scheduler.py` — 异步多用户调度器

**核心调度逻辑**:
1. 每15分钟周期开始，收集所有活跃用户
2. 按用户等级排序（VIP > PRO > BASIC > FREE）
3. 使用 TaskGroup 并发执行（用户隔离）
4. 每个用户执行: 初始化 → 风险检查 → 获取数据 → 分析 → LLM决策 → 执行交易

**风险熔断检查（v7新增，在分析前执行）**:
- 检查当日回撤是否超过 `max_drawdown_pct`
- 如超过熔断阈值，跳过本轮决策，只执行持仓管理
- 检查当前波动率体制，动态缩放仓位

**信号校验** (`validate_signal`):
- 开仓金额校验（position_size_pct 倍数上限）
- 限价单距离校验（limit_order_min_distance_pct）
- **波动率自适应校验（v7新增）**: 高波动时自动降低仓位上限

**错误处理**: 错误计数 + 连续错误检测 + 自动暂停

### 2.5 LLM 决策模块 (llm/)

#### 2.5.1 `llm/context_builder.py` — LLM 上下文构建器

**职责**: 将所有市场分析数据组装成LLM可消费的结构化输入

**核心函数**:
- `build_market_layer()`: 市场层（regime/sentiment/funding/btc/eth/exposure）
- `build_positions_layer()`: 持仓层（当前持仓/盈亏/止损止盈）
- `build_risk_layer()`: 风险层（v7新增，VaR/回撤/体制/推荐仓位）
- `build_symbols_layer()`: 币种层（每个币种的技术分析结论）
- `build_full_payload()`: 完整payload组装

设计原则: 扁平化结构，数据驱动，不含策略推荐（策略留给用户定义）

每组最多40个币种，超出分批处理

#### 2.5.2 `llm/prompt_templates.py` — Prompt 模板 v6.2

**结构**（利用首因+近因效应）:
1. `OUTPUT_ANCHOR`: 输出约束（首因效应锚定，第一时间确立输出格式）
2. `user_strategy`: 用户策略（7大类，从DB加载）
3. `CORE_ACTIONS`: 可用动作定义
4. `CORE_OUTPUT_FORMAT`: 输出格式 + 错误处理（近因效应，最后强化）

**动作类型**:
- 开仓: `open_long_market/short_market`, `open_long_limit/short_limit`
- 管理: `increase/decrease_position`, `stop_orders`, `update_stop_loss/take_profit`
- 平仓: `close_long/short`
- 不操作: `wait`（无仓位无挂单），`hold`（有仓位或挂单），`cancel`（取消挂单）

**安全**: `_sanitize_user_strategy()` 提示注入防护

**7大策略分类**:
1. `role` — 角色定义
2. `risk_rules` — 风险规则
3. `entry_conditions` — 入场条件
4. `exit_conditions` — 出场条件
5. `position_sizing` — 仓位管理
6. `market_preferences` — 市场偏好
7. `adaptive_rules` — 适应规则

**策略预设**: conservative / aggressive / trend_following / mean_reversion / default

#### 2.5.3 `llm/llm_api.py` — LLM API 调用层

**核心流程**:
1. 获取全局市场上下文
2. 获取用户持仓/订单/余额
3. **获取风险状态（v7）**
4. 获取各币种技术分析数据
5. 构建payload（market_layer + risk_layer + positions_layer + symbols_layer）
6. 组装system prompt（策略模板 + 用户策略）
7. 调用LLM API（重试3次，指数退避）
8. 解析响应 → 交易信号
9. 记录决策到数据库

**分组机制**: 每组最多40个币种
**精度处理**: `_round_floats_recursive()` 统一浮点精度，处理inf/nan

#### 2.5.4 `llm/llm_client.py` — 统一 LLM 客户端

**支持提供商**: Anthropic(Claude) / OpenAI(GPT) / DeepSeek / OpenRouter / Grok / Gemini / Custom

架构: 抽象基类 `LLMProvider` + 工厂方法 `create_client()`
- `AnthropicClient`: Claude API（Messages API）
- `OpenAIClient`: OpenAI兼容API（覆盖DeepSeek/OpenRouter/Grok/Gemini/Custom）

**特性**:
- 重试机制（指数退避，最多3次）
- 可重试: 网络错误、超时、5xx状态码
- 每提供商默认参数（temperature/top_p）
- 异步HTTP（aiohttp）

**Provider 参数**:
- anthropic: temp=0.1, top_p=0.9
- openai: temp=0.3, top_p=0.9
- deepseek: temp=0.3, top_p=0.95

> **设计注记**: 2025年Hyperliquid交易竞赛结果证明，通用LLM在不加量化约束的情况下仅能勉强跑赢市场。dashen-money的设计思路是：LLM负责"策略推理"，量化指标负责"信号过滤"，风险层负责"仓位约束"——三者缺一不可。

#### 2.5.5 `llm/response_parser.py` — 响应解析器

**支持格式**:
- OpenAI兼容格式（OpenAI/DeepSeek/OpenRouter/Grok）
- Anthropic格式（Claude）

**解析流程**:
1. 提取响应内容（content + reasoning_content）
2. 预处理: 移除 thinking/analysis 标签
3. XML解析: `<decision>[...]</decision>`
4. JSON解析: 直接JSON数组
5. 信号标准化: 统一字段名

`ParsedContent`: content/reasoning_content/raw_content

#### 2.5.6 `llm/llm_models_service.py` — LLM 模型配置服务

`LLMModel`: temperature/top_p/max_tokens/context_window/vision/function_call/input_price/output_price

`LLMModelsService`: 从DB读取，替代硬编码PROVIDER_PARAMS，缓存管理

## 八、v7 升级摘要

v7（dashen-money）核心新增与升级:

**功能升级**:
1. **风险感知层**: VaR/CVaR/最大回撤实时计算，熔断机制，波动率自适应仓位
2. **dashen-selector双模式**: 本地评分模型 + 外部API，选币更透明可控
3. **交易尸检v2**: 6类失败模式分类，自动优化建议，Telegram推送
4. **决策反馈v2**: 按市场体制分类的胜率统计，风险状态注入payload
5. **5m超短线层（可选）**: 提升入场精度
6. **风险配置API**: 用户可自定义风险参数
7. **VWAP指标**: 入场价格质量评估
8. **通知升级**: 交易信号附带风险状态摘要

**研究依据**: 以上升级基于2025年最新量化研究——多时间框架RL、风险调整优化、LLM+RL融合架构、机构级风险管理实践。
